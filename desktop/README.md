# desktop — 화면 OCR 쇼핑몰 감지 프로그램

PC 화면을 캡처해 OCR로 글자를 읽고, 쇼핑몰 화면인지 판별하는 데스크톱 프로그램입니다.
크롬 확장 프로그램이 닿지 않는 곳(다른 브라우저, 앱 등)에서도 쇼핑 시도를 감지하기 위한 것입니다.

## 원본 코드 (팀원 작품)

`original/shopping_detector.py`는 **팀원이 직접 만든 코드**입니다.

- 이 파일은 **수정하지 않습니다.** 원본 그대로 보존하고, 동작 기준(레퍼런스)으로 사용합니다.
- 기능을 고치거나 확장할 때는 아래 "구조화 계획"에 따라 새 모듈에 옮겨 작성합니다.

### 원본 동작 방식

1. `F4` 키를 누르면 주 모니터 화면을 캡처합니다 (`mss`).
2. `easyocr`(한국어+영어, CPU 모드)로 화면 속 텍스트를 추출합니다.
3. 쇼핑 키워드(장바구니, 바로구매, 결제하기 등)와 가격 패턴(`15,000원`, `₩35,000`)을 찾습니다.
4. 키워드 2개 이상 **또는** 가격 패턴 1개 이상이면 쇼핑몰로 판정하고 콘솔에 출력합니다.

## 실행 방법 (Windows)

### 1. 가상환경 준비 (최초 1회)

```powershell
cd desktop
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

> `easyocr`가 PyTorch를 함께 설치하므로 용량이 크고 시간이 걸립니다.
> `.venv/`는 Git에 올리지 않습니다 (`.gitignore`에 등록됨).

### 2. 원본 실행

```powershell
cd desktop
.\.venv\Scripts\python.exe original\shopping_detector.py
```

- 처음 실행하면 OCR 모델(한국어/영어)을 인터넷에서 내려받아 `%USERPROFILE%\.EasyOCR\`에 저장합니다. 몇 분 걸릴 수 있습니다.
- "쇼핑몰 감지 프로그램이 실행되었습니다!"가 나오면 준비 완료입니다.
- 쇼핑몰 페이지를 띄운 뒤 `F4`를 누르면 분석 결과가 콘솔에 나옵니다. CPU 모드라 한 번 분석에 수 초~십수 초 걸립니다.
- 종료는 콘솔 창에서 `Ctrl + C`.

### 문제 해결

- **F4를 눌러도 반응이 없을 때**: `keyboard` 라이브러리는 전역 키 입력을 가로채므로, 일부 환경에서는 터미널을 **관리자 권한**으로 실행해야 합니다.
- **듀얼 모니터**: 원본은 주 모니터(`monitors[1]`)만 캡처합니다. 쇼핑몰 화면을 주 모니터에 띄우세요.

### 3. 새 코드 실행 (impulse_guard 패키지)

원본과 같은 쇼핑 판정에 가격 분석(할인가, 원가, 할인율, B-1)과 서버 연동(위험도 판단, 감지 기록, B-2)을 더했습니다.

```powershell
cd desktop
.\.venv\Scripts\python.exe -m impulse_guard.main
```

### 4. 서버 연결 (B-2)

1. 웹 `http://localhost:8001/ipp/setting.php`에 로그인해서 **외부 프로그램 연결 (데스크톱 감지 프로그램)** → **발급**. 토큰은 한 번만 보입니다.
2. `local_config.example.json`을 복사해 `local_config.json`을 만들고 `token`을 넣습니다 (Git에 올라가지 않음).

   ```json
   { "server": "http://localhost:8001", "token": "64자리 토큰", "timeout_sec": 2 }
   ```

3. 실행하면 시작할 때 토큰으로 회원을 확인합니다.

```
[서버] 연결됨: http://localhost:8001 / 닉네임(아이디) / 포인트 1,250P
```

F4를 눌러 쇼핑 화면이면 서버에 위험도를 묻고 기록을 남깁니다. 충동구매로 판단하면 팝업을 띄웁니다 (5번).

```
⭕ [판정 결과] 쇼핑몰 사이트입니다!
  ...
  - 할인가: 49,600원 (확신도 0.98)
  - 원가:   119,000원 (확신도 0.98)
  - 할인율: 58% (확신도 0.80, 검산 통과)
  - 사이트: coupang / 상품명: 맨즈실렉터 대박 남자 오버핏 볼룹 겨울 패딩 / 결제 화면: 아니오
  [서버] 위험도 판단
    - 차단 시간: 아님
    - 충동구매 감지: 예
      · '패딩' 키워드가 들어 있어요.
    - 지금 포기하면 496P, 24시간 참으면 992P
    - 감지 기록 저장 (번호 107)
```

| 상황 | 동작 |
|---|---|
| `local_config.json`이 없거나 토큰이 비었음 | 오프라인 모드. 감지만 합니다 |
| 서버가 꺼져 있음, 응답이 2초를 넘음 | 오프라인 모드. F4를 누를 때 60초 간격으로 다시 연결해 봅니다 |
| 토큰이 틀림(401) | 오프라인 모드. 다시 시도하지 않습니다 → 토큰 재발급 |
| 회원 설정(차단 시간, 키워드) | 1분간 캐시 (B-4에서 5분 → 1분). 자동 감지는 쇼핑 화면에 들어설 때 다시 받습니다. 서버가 끊겨도 마지막으로 받은 설정으로 남은 차단 시간을 보여 줍니다 |

- 서버로 보내는 값: 사이트 코드, 상품명, 할인가, 원가, 할인율, 결제 화면 여부. **캡처 이미지는 보내지 않습니다.**
- 사이트는 화면 글자(로고 `coupang`, `MUSINSA`, `ZIGZAG`, 서버 사이트 이름)로 찾고, 모르면 `""`로 보냅니다. 상품명은 할인가 위쪽의 가장 큰 글자 줄이라 OCR 오류가 그대로 들어갑니다.
- API 명세: [docs/API.md](../docs/API.md)

### 5. 차단 팝업 (B-3)

tkinter(Python 기본 포함)로 만든 창이라 추가 설치가 없습니다. 창은 항상 다른 창 위, 주 모니터 위쪽 가운데에 뜹니다. 글꼴은 맑은 고딕입니다.

| 상황 | 동작 |
|---|---|
| 차단 시간 (웹 설정의 차단 중) | **차단 안내 창**: 남은 시간(1초마다 줄어듦)과 [확인]. 기록은 `blocked`. 쇼핑몰 전체 차단(기본 켬)이면 모든 쇼핑 화면, 끄면 설정에서 켜 둔 사이트만 (사이트를 모르면 차단 시간만 봄) |
| 충동구매 감지 | **충동구매 팝업**: 상품명, 할인가, 원가와 할인율(있으면), 이유 1~2개, 예상 포인트, 버튼 세 개 |
| 쇼핑 화면인데 가격을 못 읽음 | 충동구매 팝업에 "가격을 읽지 못했어요". 담아두기는 꺼지고, 안 살래요는 포인트 없이 기록만 |
| 충동구매 아님 | 콘솔 출력만 |
| 오프라인 | 팝업 없이 콘솔 안내 "(오프라인이라 알림 창은 띄우지 않았습니다)" |

| 버튼 | 서버 | 결과 |
|---|---|---|
| 조금 더 생각하기 (24시간 담아두기) | `cooldown` + `bl_id` | 같은 창에 "타임머신에 담았어요, OO까지 참으면 +OOP" / 타임머신 보기(웹) |
| 안 살래요 | `giveup` + `bl_id` | 같은 창에 "+OOP를 받았어요" (하루 상한이면 그 안내) |
| 그래도 구매할래요 | `decide buy` | 창을 바로 닫고 기록은 뒤에서 보냄 |
| 창의 X | `decide close` | 닫기. 포인트 없음 |

- 서버 요청이 실패하면 창에 빨간 안내를 띄우고 다시 누를 수 있습니다.
- 창이 떠 있거나 분석 중일 때 누른 F4는 무시하고 콘솔에 안내합니다. 창을 닫으면 다시 받습니다.
- 스레드: 창은 main 스레드(tkinter mainloop)만 다룹니다. F4 콜백은 작업 스레드를 띄우기만 하고, 분석과 서버 요청은 작업 스레드에서 합니다. 결과는 큐로 main 스레드에 넘깁니다 (`popup.UiHost.post`).

### 6. 자동 감지 (B-4)

F4를 누르지 않아도 화면을 확인합니다. F4는 디버그·백업용으로 남아 있습니다 (중복 검사 없이 바로 분석).

```jsonc
// local_config.json (없으면 아래 기본값, 예시: local_config.example.json)
"auto_detect": {
  "enabled": true,            // 자동 감지 켜기/끄기
  "interval_sec": 3,          // 화면 확인 간격 (1~60)
  "same_order_minutes": 10,   // 같은 주문은 마지막으로 본 뒤 이 시간 안에 다시 알리지 않음
  "blocked_repeat_sec": 60,   // 차단 안내 창을 닫은 뒤 같은 쇼핑몰에서 다시 띄우기까지
  "save_ocr_text": false,     // C-1 학습용 OCR 원문 저장 (상품 화면/쇼핑 아님만, 개인정보 마스킹)
  "exclude_programs": ["Code.exe", "WindowsTerminal.exe", "OpenConsole.exe", "conhost.exe",
                       "cmd.exe", "powershell.exe", "pwsh.exe"]   // 맨 앞 창이 이 프로그램이면 건너뜀 ([]: 제외 없음)
}
```

**한 회차** (`auto_detect.py`): 캡처와 해시는 0.1초 정도라 3초마다 해도 가볍고, 9초 걸리는 OCR은 필요할 때만 합니다.

1. 알림 창이 떠 있거나 분석 중이면, 또는 맨 앞 창이 이 프로그램의 콘솔이거나 감지 제외 프로그램(`exclude_programs`, 실행 파일 이름, 대소문자 무시)이면 쉰다
2. 캡처 → 화면 해시(dHash 256비트)
3. 직전에 분석한 화면과 거의 같으면(6비트 이하) OCR을 건너뛴다
4. 바로 앞 회차와 많이 다르면(12비트 초과) 아직 바뀌는 중(스크롤, 이동)이라 1초 뒤 다시 본다. 멈췄으면 OCR. 광고 배너처럼 조금씩 움직이는 화면도 멈춘 것으로 본다
5. F4가 방금 분석한 화면은 다시 OCR하지 않고, F4로 띄운 결제 화면 팝업도 같은 주문으로 기억한다

결제 화면에 들어선 뒤 팝업까지는 대략 1~4초(멈춤 확인) + OCR 약 10초가 걸립니다. 시작할 때 콘솔과 로그에 자동 감지 설정을 어디서 읽었는지(`local_config.json` 또는 기본값) 남깁니다.

**화면 단계** (`detector/stage.py`): 결제 키워드 점수(`config.CHECKOUT_KEYWORDS`)가 4점 이상이고 서로 다른 키워드가 2개 이상이면 결제 화면, 아니면 원본 규칙으로 상품 화면/쇼핑 아님. 키워드는 공백을 빼고, OCR이 자주 틀리는 글자(`config.CHECKOUT_OCR_FIXES`, 예: '좀 결제금억' → '총결제금액')를 고친 뒤 비교합니다. 실제 결제 화면 캡처 2장(무신사, 지그재그)으로 보정했습니다.

| 단계 | 차단 시간 아님 | 차단 시간 |
|---|---|---|
| 쇼핑 아님 | 로그만 | 로그만 |
| 상품 화면 | 로그와 쇼핑몰별 마지막 상품만 기억 (**서버 호출 없음**) | 차단 안내 창 + `blocked` 기록 |
| 결제 화면 | 서버 기록(`is_checkout`) + **항상** 충동구매 팝업 ("결제하기 전에 잠깐만요!") | 차단 안내 창 + `blocked` 기록 |

- 결제 금액: '최종 결제금액', '총 결제금액' 등 라벨과 같은 줄 오른쪽의 가격 (없으면 바로 아래 줄). 못 찾으면 할인가, 그것도 없으면 "가격을 읽지 못했어요"
- 결제 화면 상품명: 같은 쇼핑몰에서 30분 안에 본 상품 이름 → 결제 화면에서 읽은 이름 → "쿠팡 주문"처럼 쇼핑몰 이름 순서
- 차단 여부: 상품 화면은 서버를 부르지 않으므로 캐시된 설정(1분)으로 판단합니다. 쇼핑 아님 → 쇼핑 화면으로 바뀌는 순간에는 캐시를 무시하고 서버에서 다시 받아, 방금 시작한 차단도 놓치지 않습니다.

**중복 방지** (`dedup.py`)

- 같은 주문: 쇼핑몰 + 결제 금액이 같으면 (금액을 못 읽었으면 화면 해시 거리 20 이하)
- 기준 시간은 **마지막으로 본 시각부터** 10분입니다. 결제 화면에 계속 머물면 다시 뜨지 않고, 다른 창에 갔다 10분 안에 돌아와도 다시 뜨지 않습니다 (로그에 `revisit`). 10분 넘게 떠나 있었다면 새 시도로 봅니다.
- 팝업에서 무엇을 골랐든(안 살래요, 조금 더 생각하기, 그래도 구매, X) 그 주문의 팝업은 다시 띄우지 않습니다.
- 차단 안내 창은 닫은 뒤 같은 쇼핑몰에서 `blocked_repeat_sec` 동안 다시 띄우지 않습니다.
- 기억은 프로그램이 켜져 있는 동안만 메모리에 둡니다.

**로그** (`logs/`, Git에 올리지 않음)

```
2026-11-11 21:03:12 INFO auto | 결제 화면 | coupang | 49,600원 | 점수 13/4 [주문/결제 3, 총결제금액 3, 결제하기 2, ...] | new | → popup | OCR 8.9초 | detect 기록 131번
2026-11-11 21:05:40 INFO auto | 결제 화면 | coupang | 49,600원 | 점수 13/4 [...] | revisit | 120초 만에 다시 옴, 결정: giveup
```

- `detect.log`(1MB × 5개): 시간, 출처(auto/f4), 단계, 쇼핑몰, 금액, 점수와 근거, 중복 여부(new/same/revisit/wait), 동작, OCR 시간. 같은 화면이라 OCR을 건너뛴 회차는 DEBUG로 남깁니다.
- 콘솔에는 단계가 바뀌거나 동작이 있을 때만 출력합니다.
- `ocr_samples.jsonl`(save_ocr_text가 true일 때만): 상품 화면/쇼핑 아님의 OCR 원문. 이름, 전화번호, 주소, 카드번호, 이메일 패턴을 가립니다. 결제 화면은 저장하지 않습니다.
- **캡처 이미지는 어디에도 저장하지 않습니다.**

**알림 창 포커스**: 자동 감지로 띄운 창은 포커스를 가져가지 않고 작업 표시줄만 깜빡입니다 (브라우저에서 치던 키가 버튼을 누르지 않게). F4로 띄운 창은 포커스를 가져옵니다. 창이 뜬 뒤 0.7초 동안은 버튼 입력을 무시하고, 떠 있는 동안 2초마다 맨 위로 다시 올립니다.

**한계**: 화면 전체를 OCR하므로 화면이 자주 바뀌면 CPU를 많이 씁니다 (B-5에서 활성 창만, 축소). 감지 제외는 맨 앞 창 기준이라, 브라우저가 맨 앞이어도 화면 한쪽에 보이는 편집기/터미널의 글자는 함께 읽힙니다 (B-5의 활성 창 캡처로 해결).

## 구조

원본은 그대로 두고, 같은 동작을 기능별 모듈로 나눈 `impulse_guard/` 패키지를 새로 만들었습니다 (B-1). B-2에서 서버 연동을 더했습니다.

### 가격 분석 방법 (`detector/price.py`)

1. **후보 찾기**: `49,600원`, `₩35,000`, `56,000` 같은 가격과 `58%` 같은 할인율을 찾습니다. 숫자와 `원`이 다른 상자로 나뉘면 합칩니다.
2. **OCR 오류 보정**
   - **취소선 가격 다시 읽기**: 취소선이 있으면 OCR이 원가를 `#49G68원`처럼 읽습니다. 취소선 구간만 잘라 선을 지우고 3배 확대해 숫자만 허용해서 다시 읽습니다 (`ocr.read_struck`).
   - **`%` 오인식**: EasyOCR은 `58%`를 `5896`으로 읽습니다. 상자 하나가 통째로 `숫자+96`이고 바로 오른쪽에 가격이 있을 때만 할인율로 봅니다.
   - **형식 검사**: 쉼표 없는 큰 숫자(`444366원`), 깨진 글자 사이의 숫자(`35B,888원`의 888)는 형식 이상으로 감점합니다.
3. **단서 점수 (0~1)**: 후보마다 `features`에 따로 남깁니다. 나중에 학습 모델의 특성으로 씁니다.

   | 단서 | 내용 |
   |---|---|
   | `size` | 글자 높이 ÷ 가격 후보 중 가장 큰 높이 |
   | `strike` | 가운데 높이를 가로지르는 선이 있는지 |
   | `color_red`, `color_gray` | 글자 대표 색이 빨강인지, 회색인지 |
   | `ctx_sale`, `ctx_orig`, `ctx_other` | 주변에 판매가/쿠폰적용가, 정가/소비자가, 배송비/적립/최대/쿠폰 같은 단어가 있는지 |
   | `near_rate` | 상품 할인율과 가까운지 |
   | `pos_top` | 화면 위쪽일수록 1 |
   | `repeat` | 같은 금액이 여러 번 나오는지 |
   | `ocr_conf`, `format_ok` | OCR 확신도, 쉼표 형식 |

4. **역할 점수**: 단서 점수 × 가중치(`config.ROLE_WEIGHTS`)의 합으로 할인가, 원가, 기타 점수를 냅니다.
5. **할인율 검산**: `|1 − 할인가/원가 − 할인율| ≤ 1.5%p`인 조합 중 점수가 가장 높은 것을 고릅니다. 사이트가 할인율을 반올림해서 보여 주므로(220,590/258,000 = 14.5% → 15%) 할인율 차이로 비교합니다. 맞지 않는 가격은 OCR 오류로 제외합니다.
   - `쿠폰`, `최대`, `첫 구매`, `평가` 등이 같은 줄에 있는 %(예: 첫 구매 20% 쿠폰)는 상품 할인율로 쓰지 않습니다.
   - 할인율이 없거나 검산이 안 되면 역할 점수만으로 정하고 `verified = False`로 둡니다.
6. **결과** `PriceResult`: 할인가, 원가, 할인율, 각각의 확신도, 검산 여부, 후보별 단서와 점수

## 테스트

OCR은 느리므로 테스트 이미지의 OCR 결과를 `tests/ocr_cache/*.json`에 저장해 두고 다시 씁니다.

```powershell
cd desktop
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v   # 전체 테스트
.\.venv\Scripts\python.exe -X utf8 tests\price_report.py              # 이미지별 가격 분석 표 (-v: 단서 점수까지)
.\.venv\Scripts\python.exe tests\make_ocr_cache.py                    # OCR 캐시 다시 만들기 (이미지를 바꿨을 때)
.\.venv\Scripts\python.exe tests\make_ocr_cache.py --reread-only      # 취소선 다시 읽기만 새로 (취소선 판정을 바꿨을 때)
```

## 진행 원칙

- 쇼핑 판정 결과는 원본과 같아야 합니다. `config.py`의 원본 값을 바꾸면 `test_shopping.py`가 실패합니다.
- 설정값은 `config.py` 한곳에 모읍니다.
- tkinter 창은 main 스레드에서만 만들고 고칩니다. 다른 스레드는 `UiHost.post()`로 넘깁니다.
- 서버 통신은 `server_client.Client.call()` 하나를 지납니다. 테스트는 `transport`(HTTP 호출)와 `clock`(시각)을 가짜로 바꿔 서버 없이 확인합니다.
- 캡처 이미지는 파일로 저장하거나 서버로 보내지 않습니다.
