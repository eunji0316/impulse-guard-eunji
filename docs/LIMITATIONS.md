# impulse-guard 알려진 한계

7 마무리에서 `docs/PROGRESS.md`의 남은 이슈를 모았다. 시연 전에 고칠 것은 고쳤고(통계 화면 결제 화면 팝업 칸, 실행 스크립트),
여기 있는 것은 **고치지 않고 한계로 남긴 것**이다. 각 항목의 자세한 내용은 괄호의 PROGRESS 단계 절에 있다.

## AI 모델

| 한계 | 영향 | 다음에 할 일 |
|---|---|---|
| 화면 분류·위험도 모두 **가상 데이터로 학습** (C-1, C-2) | 점수는 실제 성능의 증거가 아니다 | 예측마다 원시 값·모델 버전을 기록하고 있으므로, 결정이 쌓이면 `ai/data/export.py`에 C-2 추출을 더해 실제 데이터로 평가 |
| 화면 분류 실측 18장, 결제 화면은 대부분 넓은 창 (C-1) | 좁은 창, 모바일형 결제 화면은 덜 검증됨 | 실측을 더 모아 깨끗한 평가 |
| 가상 결제 화면에 원가·할인율·상품 주소가 없음 (C-1) | 결제 화면에 할인율이 보이면 상품 화면 쪽으로 기움 (11번가 0.61 사례). 결제 키워드 우선 규칙으로 막음 | 생성기 수정 |
| 결제 키워드 우선 규칙의 장바구니 오탐 0건은 가상 데이터 기준 (C-1) | 실제 장바구니에서 결제 화면으로 볼 수 있음 | 실제 장바구니 캡처로 확인 |
| '그래도 구매' ≠ 충동구매, '안 살래요'에 포인트가 붙음 (C-2) | 라벨에 잡음 | mock 은행의 24시간 뒤 실제 구매를 더 강한 라벨로 |
| 상품 화면 특성은 메모리에만, 같은 상품은 상품명 해시 (C-2) | 프로그램을 다시 켜면 0부터, OCR이 상품명을 다르게 읽으면 다른 상품 | - |
| AI 요약 숫자 검사는 '세 번'처럼 글자로 쓴 수를 못 잡음 (5) | 지어낸 숫자가 글자로 나오면 통과 | 실제 API로 품질 확인 |
| AI 요약은 실제 Claude API로 확인하지 않음 (5) | 가짜 클라이언트 테스트만 | API 키를 만든 뒤 PROGRESS 5 절 순서로 확인 |

## OCR과 가격 분석

| 한계 | 사례 |
|---|---|
| 배송비·리뷰 수를 가격으로 읽음 | 올리브영 상품 화면: 할인가 5,000원(배송비), 원가 6,086(리뷰 수)으로 17% 검산 통과 (C-2) |
| 글자 오인식 | 지그재그 결제 화면 0.8배 '최대'→'최며'로 혜택 금액이 상품 할인가로 남음 (결제 금액은 정상) (C-2) |
| 숫자 뒤 'P'(포인트)가 가격 후보 | 11번가 0.9배 '9,120P' (지금은 적립 문맥으로 빠짐) (C-2) |
| 상품명은 OCR 글자 그대로 | '특가'를 '특기'로 읽으면 키워드 검사가 빗나감 (B-2) |
| 가격 가중치는 적은 테스트 이미지에 맞춘 규칙 | 다른 화면 구조에서 틀릴 수 있음 (B-1) |

## 데스크톱 동작

| 한계 | 비고 |
|---|---|
| 감지 → 팝업 약 1.5초, 화면 바뀜 → 팝업 결제 페이지 제목일 때 2~3초, 아닐 때 최대 5초 | B-5 전 10~13초에서 줄임. "인식 속도 9.8~12.9초" 이슈는 B-5에서 해결됨 |
| 팝업이 키보드 포커스를 못 가져갈 수 있음 | Windows가 앞 창 빼앗기를 막음. 맨 위에는 뜸 (B-3) |
| 팝업이 떠 있는 동안 F4는 무시 | 한 번에 하나만 처리 (B-3) |
| 쿠팡 결제 페이지 창 제목은 직접 확인 못 함 | 시연 전 확인 (B-5) |
| 서버가 꺼져 있으면 '연결 실패' 대신 '응답 시간 초과'로 보임 | Windows가 닫힌 포트에 다시 시도함 (B-2) |
| '그래도 구매' 뒤 실제 결제 여부는 모름 | 기록만 (B-3) |

## 서버와 웹

| 한계 | 비고 |
|---|---|
| `php -S`는 요청을 하나씩 처리 | AI 요약을 기다리는 동안(최대 10초) 데스크톱 `check`도 기다림. 그래서 버튼으로만 부름 (5). 실제 배포는 Apache 등 |
| `check`의 `site`는 `IPP_BLOCK_SITES` 코드만 | 모르는 쇼핑몰은 `''`로 기록 (A) |

| 설정 화면 '위험도 알림'(`st_risk_alert`)은 저장만 | 실제 알림 없음 |
| 회원별 감지 기준 없음 (`IPP_DETECT_*` 전역 상수) | - |
| 차단 이력은 마지막 1건만 | - |
| 회원이 자기 기록을 지우는 화면 없음 | `docs/PRIVACY.md` |
| 기프티콘 발급·사용 확인은 mock, 바코드 없음, `pending` 쿠폰 환불 없음 | 실제 업체 API 연동 전 (기프티콘 단계) |
| 리워드 관리자 페이지 없음, `002_gifticon.sql`을 다시 실행하면 시연 리워드 중복 | DB에서 직접 관리 |
| '안 살래요' 포인트 악용 | 하루 상한(`IPP_DAILY_LIMIT`)만 막음 |

## 보류: 크롬 확장 프로그램 (`extension/`, `IPP_USE_EXTENSION = false`)

데스크톱 감지로 방향을 바꾸며 보류했다 (A-5). 아래 이슈는 확장 프로그램을 다시 쓸 때만 해당한다.
지그재그 가격·구매 흐름·장바구니 선택자, 나머지 4개 사이트, 쿠팡 Tailwind 선택자, 대표 이미지, 차단 화면 깜빡임과 반영 지연,
`pagehide` 기록 유실, click 외 결제 이벤트, 사용자 활성화, 쿨다운 출처(`manual`), 아이콘 (PROGRESS 3단계 절).

## 해결되었지만 PROGRESS에 열린 채로 남은 항목

- 인식 속도 9.8~12.9초 → B-5에서 약 1.5~5초
- API.md 성공 응답 검증 → B-2 이후 실제 데스크톱 호출로 응답 예시를 맞춤
- 감지 기록 중복(F4 반복) → B-4 같은 주문 판단
- 통계에 감지 출처·팝업 버튼별 수 없음 → 7에서 통계 화면 '최근 7일 결제 화면 팝업' 추가 (출처별 구분은 아직)
