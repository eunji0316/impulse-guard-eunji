# impulse-guard 시연 시나리오

웹 → 데스크톱 감지 → 팝업(위험도) → 통계 → (선택) AI 요약 순서로 약 7~10분.
모든 명령은 저장소 루트(`c:\projects\impulse-guard-eunji`)의 PowerShell에서 실행한다.

## 시연 전 준비 (전날)

| 할 일 | 명령·확인 |
|---|---|
| 데모 회원과 최근 2주 기록 넣기 | `php scripts\demo_seed.php add` → 아이디 `demo`, 비밀번호 `demo1234`, `desktop\local_config.demo.json` 생김 |
| 한 번 켜 보기 | `powershell -ExecutionPolicy Bypass -File scripts\start.ps1 -Demo` → 상태 표에 웹 서버·예측 서버 '응답함' |
| 시연할 쇼핑몰 정하고 한 번 돌려 보기 | 할인 중인 상품 → 바로구매 → 결제 화면까지. 무신사, 11번가, 컬리는 화면 분류 실측에서 맞혔다. 쿠팡은 결제 페이지 창 제목을 아직 확인하지 않았다 |
| 브라우저 창 | 데스크톱 주 모니터, 넓은 창 (좁은 창·모바일형 결제 화면은 덜 검증됨) |
| 알림 끄기 | Windows 방해 금지 (팝업 위에 다른 알림이 겹치지 않게) |
| AI 요약을 보여 줄지 정하기 | 아래 6단계. 보여 준다면 API 키로 미리 한 번 확인 (README 'AI 주간 리포트 요약 켜기') |
| 끄기 | `powershell -ExecutionPolicy Bypass -File scripts\stop.ps1` |

`start.ps1 -Demo`가 하는 일: 웹 서버에 `IPP_RISK_SERVER=on`(위험도를 예측 서버로 계산)을 넘기고, 데스크톱이 데모 회원 설정으로 연결한다.
설정 파일(`extend/ipp.extend.php`)은 바꾸지 않는다. 이미 직접 켠 8001 서버가 있으면 먼저 끈다.

## 시연 순서

| 단계 | 할 일 | 보여 줄 것 | 말할 것 |
|---|---|---|---|
| 1. 켜기 | `start.ps1 -Demo` (AI 요약까지면 `-Demo -Llm`) | 새 창 3개(웹 서버, 예측 서버, 데스크톱), 상태 표 | 웹·예측 서버·데스크톱 감지 프로그램이 각각 돈다 |
| 2. 웹 | `http://localhost:8001` → `demo` 로그인 → 통계 화면(`/ipp/stats.php`) | 최근 7일 예상 절약, 차단, **최근 7일 결제 화면 팝업**(버튼별, 위험 단계별) | 지난 2주 기록이 쌓인 회원이다 |
| 3. 상품 화면 | 쇼핑몰 할인 상품 페이지를 열고 5초쯤 둔다 | 데스크톱 콘솔에 `상품 화면` 한 줄, **팝업 없음** | 화면 글자만 읽어 상품 화면으로 분류했다 (C-1). 할인율·머문 시간은 메모리에만 센다 |
| 4. 결제 화면 | 바로구매 → 주문서 | 1.5~5초 안에 **팝업**: 위험 배지(낮음/보통/높음), 제목 색, 보통 이상이면 이유 최대 3개 | 결제 화면을 감지하고 위험도를 계산했다 (C-2). 이유는 모델의 특성별 기여다 |
| 5. 버튼 | '안 살래요' 또는 '24시간 담아두기' | 포인트 안내, 통계 화면을 새로고침하면 결제 화면 팝업 칸의 숫자가 1 늘어남 | 고른 버튼은 다음 위험도 학습의 라벨이 된다 |
| 6. (선택) AI 요약 | 통계 화면 **AI 요약 보기** | 아래 표 | 집계 숫자만 보내고, 보낸 숫자만 쓰는지 검사한다 |
| 7. 끄기 | `stop.ps1` | 창이 닫힘 | |

### 6단계 화면 (AI 요약)

| 상황 | 통계 화면 |
|---|---|
| `-Llm` 없이 켬 (기본) | AI 요약 칸이 **없다**. 다른 칸은 그대로 |
| `-Llm`으로 켰고 API 키가 있음 | 버튼 → '요약을 만드는 중이에요...' → 몇 초 뒤 굵은 제목 한 줄, 요약 3문장 이내, 💡 제안 한 줄 |
| `-Llm`으로 켰지만 **API 키가 없음** | 버튼 → '요약을 만드는 중이에요...' → **'지금은 요약을 만들 수 없어요.'** 다른 칸은 그대로. `start.ps1`이 켤 때 키가 없다고 미리 알려 주고, `/health`의 `message`가 `null` |
| 예측 서버가 꺼짐 | 위와 같은 문구. 60초 동안은 버튼을 눌러도 바로 같은 문구 |

- 버튼을 누르고 기다리는 동안(최대 10초) 웹 서버가 다른 요청을 처리하지 못한다 (`php -S`). **결제 화면 감지 중에는 누르지 않는다**
- 데모 회원 기록 기준 예상 내용: 이번 주는 '그래도 구매'가 줄고(지난주 4번 → 1번) 참은 비율이 43% → 80%로 오름

## 문제가 생기면

| 증상 | 대처 / 말할 것 |
|---|---|
| 예측 서버가 꺼짐 | 팝업은 그대로 뜬다. 서버 PHP가 같은 모델로 계산한다 (C-3 자동 전환) |
| 결제 화면인데 팝업이 늦음 | 결제 금액이 화면에 안 보이면 '결제 금액 확인 중' 팝업이 먼저 뜨고, 스크롤해서 금액이 보이면 채워진다 |
| 팝업이 안 뜸 | 데스크톱 콘솔에서 단계 확인 (`쇼핑 아님`이면 창을 넓히거나 결제 버튼이 보이게 스크롤). 브라우저가 맨 앞 창인지 확인 |
| 웹 서버 응답 없음 | `stop.ps1` 뒤 `start.ps1 -Demo` 다시. 8001을 다른 프로그램이 쓰는지 확인 |
| 위험도가 늘 낮음 | 낮음도 정상이다. 심야, 큰 금액, 할인, 같은 상품 반복이면 올라간다 |

## 시연이 끝나면

```powershell
powershell -ExecutionPolicy Bypass -File scripts\stop.ps1
php scripts\demo_seed.php remove      # 데모 회원과 시연 중 생긴 기록, 데모 설정 파일까지 지움
```
