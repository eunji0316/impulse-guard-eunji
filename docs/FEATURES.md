# impulse-guard 기능 정리

> A-5단계(2026-11-11) 방향 전환 후의 기능 목록입니다. 괄호는 (기존/수정/신규, 필수/선택)입니다.

# 전체 구성
- 데스크톱 감지 프로그램(Python, 팀원 코드 기반): 화면 캡처 → OCR → 쇼핑 화면 판별 → 위험도 판단 → 팝업
- 서버와 웹(그누보드): 포인트, 쿨다운, 기프티콘, 설정, 기록과 통계
- 화면: 모바일 웹(PWA), PC 웹 대시보드

# 1. 데스크톱 감지 프로그램 (핵심)
- 화면 캡처: 전체 화면 대신 현재 활성 창만 캡처 (수정, 필수)
- OCR 글자 인식: EasyOCR (기존, 필수)
- 쇼핑 화면 판별: 키워드 규칙을 AI 분류 모델로 교체 (수정, 필수)
- 가격 분석: 원가, 할인가, 기타(배송비, 적립금)를 구분. 글자 크기, 취소선, 색, 주변 단어, 위치를 단서로 쓰고 할인율로 검산해 OCR 오류 제거 (신규, 필수)
- 결제 화면 감지: 결제하기, 주문서, 배송지 등을 감지하면 위험도 상향 (신규, 필수)
  - B-4 완료: 결제 키워드 점수(4점 이상, 서로 다른 키워드 2개 이상)로 "쇼핑 아님 / 상품 화면 / 결제 화면"을 판정하고 근거(키워드, 점수)를 남긴다
  - 결제 화면이면 서버가 `checkout` 이유를 붙여 항상 팝업. 결제 금액은 '최종 결제금액' 등 라벨 옆에서 찾는다
- 자동 감지: 활성 창 제목에 쇼핑몰 이름이 있거나 화면이 바뀌면 자동 분석 (신규, 필수)
  - B-4 완료: F4 없이 3초마다 캡처 → 화면 해시로 바뀌고 멈춘 화면만 OCR. 상품 화면은 기록 없이 상태만, 결제 화면은 기록과 팝업
  - 같은 주문(쇼핑몰+결제 금액, 또는 화면 해시) 중복 방지: 마지막으로 본 뒤 10분, 팝업 결정 기억, 차단 안내는 60초 간격
  - 감지 로그(시간, 단계, 쇼핑몰, 금액, 점수, 중복 여부)와 C-1 학습용 OCR 원문(선택, 결제 화면 제외, 개인정보 마스킹). 캡처 이미지는 저장하지 않음
  - 설정: `local_config.json`의 `auto_detect` (켜기/끄기, 간격, 같은 주문 시간, 차단 안내 간격, OCR 원문 저장)
  - 남은 것: 활성 창 제목 단서와 활성 창만 캡처는 B-5
- F4 수동 분석: 시연, 테스트용으로 유지 (기존, 선택). B-4부터 디버그·백업용 (중복 검사 없음)
- 차단 팝업: 항상 위에 뜨는 창. 조금 더 생각하기(24시간), 안 살래요, 그래도 구매 (신규, 필수)
- 차단 모드: 차단 시간 중 쇼핑 화면이 뜨면 차단 안내와 남은 시간 표시 (신규, 필수)
- 서버 연결: 토큰 인증 API를 데스크톱용으로 사용 (수정, 필수)
- 트레이 아이콘: 실행 상태, 일시 정지, 대시보드 열기 (신규, 선택)
- 개인정보 보호: 캡처 이미지는 저장, 전송하지 않고 분석 후 즉시 삭제. 서버에는 상품명, 가격 등 필요한 정보만 전송 (신규, 필수)
- 성능 개선: 이미지 축소, 화면이 바뀌지 않으면 분석 생략 (신규, 필수)

# 2. AI 기능
- OCR: 사전학습 딥러닝 모델 EasyOCR (기존, 필수)
- 쇼핑 화면 분류 모델: OCR 텍스트로 쇼핑/일반 화면 판별 (TF-IDF + 로지스틱 회귀 등), 학습 데이터 수집 도구 포함 (신규, 필수)
  - C-1 진행: 문자 n-gram TF-IDF + 로지스틱 회귀로 쇼핑 아님/상품 화면/결제 화면 3분류. 가상 데이터(가상 쇼핑몰 + 헷갈리는 일반 화면 + OCR 노이즈)로 학습, 데스크톱은 JSON 모델을 numpy로 계산. 저신뢰/실패 시 키워드 판정. 장바구니는 상품 화면, 주문 완료/내역은 쇼핑 아님 (`ai/screen/README.md`)
- 가격 역할 분류: 처음엔 규칙 점수, 나중에 가격 상자별 원가/할인가/기타 분류 모델로 전환 (신규, 선택)
- 충동구매 위험도 모델: 4-1의 특성과 데이터에 OCR 특성(압박 문구, 결제 화면 여부, 할인율) 추가 후 학습 (수정, 필수)
  - C-2 완료: 결제 화면 팝업 1건 = 1행, 라벨은 팝업 결정. 서버 시각·DB 과거 기록·데스크톱 상품 화면 숫자(할인율, 압박 문구, 반복 방문, 머문 시간)로 로지스틱 회귀. 서버 check가 PHP로 계산해 위험도·단계(낮음/보통/높음)·이유를 주고, 팝업은 단계별 제목·색, 이유는 보통 이상만. 포인트와는 연결하지 않음 (`ai/risk/README.md`)
- 예측 서버: 모델을 API로 제공, 실패 시 기존 규칙으로 대체 (신규, 필수)
  - C-3 완료 (축소판): FastAPI `ai/serve`가 위험도 확률·이유만 계산하고(`POST /risk/predict`, 127.0.0.1:8002), 단계·문구·기록은 서버 PHP. 기본 꺼짐(`IPP_RISK_SERVER`), 켜도 실패하면 PHP 계산으로 자동 전환하고 60초 건너뜀. 원시 값 숫자 13개만 보냄. 5단계 LLM 문구를 같은 서버에 서비스로 붙이는 구조 (`ai/serve/README.md`)
- LLM 맞춤 메시지: 팝업 문구, 주간 리포트 요약 (신규, 선택)
  - 5 진행 (주간 리포트 요약만): 통계 화면 'AI 요약 보기' 버튼 → 서버 PHP 주간 집계(숫자·이유 코드만, 쇼핑몰은 개수만) → 예측 서버 `/message/weekly` → Claude API `claude-haiku-5-5`. 증감·배수·비율은 PHP가 미리 계산해 보내고 LLM은 계산하지 않음. 입력에 없는 숫자 등 검사 후 표시, 저장하지 않음. 기본 꺼짐(`IPP_USE_LLM`), 키는 예측 서버 환경변수에만. 팝업 문구는 C-2 라벨에 영향을 줘서 하지 않음 (`ai/serve/README.md`)
- 발표용 설명: OCR → 쇼핑 화면 분류 → 위험도 예측의 3단계 AI 파이프라인

# 3. 서버와 웹 (기존)
- 포인트 지급: 절약 금액 1%, 최소 10P, 최대 500P, 하루 상한 1,000P (기존)
- 쿨다운 타임머신: 24시간 참으면 더블 포인트. 데스크톱 출처 구분 값 추가 (수정)
- 기프티콘 리워드: 포인트 교환, 쿠폰함, 발급은 mock (기존)
- 회원 설정: 차단 시간, 키워드 유지. 사이트 토글은 쇼핑몰 감지 예외 목록으로 의미 변경 (수정)
- 기록과 통계: 감지 출처 구분, 오늘 차단 상품 수와 쇼핑 시도 수 분리 (수정)
  - 7: 통계 화면에 최근 7일 결제 화면 팝업 (버튼별, 위험 단계별, 심야, 쇼핑몰 수). 감지 출처별 구분은 아직
- 토큰 인증 API: 확장 프로그램 전용에서 데스크톱 공용으로 정리 (수정)
- mock 은행 연동: 24시간 뒤 실제 구매 여부 검증용 (기존)

# 4. 화면 (UI, 여유가 되면)
- 모바일 웹(PWA): 메인, 구매 기록, 설정, 리워드, 쿠폰함 (선택)
- PC 웹 대시보드: 홈, 차단 설정, 통계와 리포트 (선택)
- 7 결정: 6 UI는 따로 하지 않고 시연에 필요한 통계 칸만 추가. 시연은 `docs/DEMO.md`, 한 번에 켜기는 `scripts/start.ps1`
- 데스크톱 팝업: 기능 동작에 필요해서 필수
- 시안의 PC 프로그램 화면은 팝업과 트레이만 데스크톱에, 대시보드는 웹으로 분리
