## 2026-11-13 · C-2: 충동구매 위험도 모델 (feature/risk-model, 구현 완료 · 실제 화면 확인 대기)

결제 화면에서 이번 구매의 충동구매 위험도(0~1)와 주요 이유를 예측한다.

### 결정 사항 (사용자 승인)

- 실행 위치: **서버 `check` 안에서 PHP로 계산** (로지스틱 회귀 계수 JSON). C-3 FastAPI는 나중에 같은 JSON으로 붙인다. 모델이 없거나 실패하면 지금 규칙(reasons)
- 모델: 로지스틱 회귀 우선. 이유는 특성별 기여(계수 × (값 − 평균)) 상위를 문장으로
- 라벨: 1 = 그래도 구매(buy), 담아두기 → 쿨다운 failed / 0 = 안 살래요(giveup), 담아두기 → success·gaveup / 제외 = X 닫기(close), 결과 없음. 가상 데이터로 시작하고, 예측할 때 특성·위험도·모델 버전을 숫자로 기록해 나중에 실제 라벨과 짝짓는다
- 상품 화면 숫자 특성(반복 방문, 머문 시간, 압박 문구)은 **결제 화면 `check`에 숫자로만** 함께 보낸다. OCR 원문, 상품명, 주소는 보내지 않는다
- 상품 화면 사전 경고는 이번에 하지 않는다 (남은 이슈)
- 포인트 차등은 C-2에서 하지 않는다 (위험도를 일부러 올려 포인트를 받는 악용 방지)

### 0. 상품 화면 가격 입력 정리 (할인율이 위험도 특성이라 먼저)

- **혜택/적립 금액 제외** (커밋 `811fc05`): 상품 화면 가격 분석에도 `benefit_word()`를 적용 (`config.PRICE_BENEFIT_WORDS`, '쿠폰'·'할인'은 빼고 판매가 라벨을 먼저 지움).
  재현: 무신사 결제 화면 Windows OCR 1배에서 '최대 32,500원 혜택'과 '6,180원 구매 적립'이 80%로 검산 통과 → 원가/할인가로 뽑힘. 고친 뒤 할인가 79,000원
- **할인가 옆 할인율** : Windows OCR(기본 엔진)은 취소선 원가를 자주 깨뜨려(`모들8;eee큗`) 원가와 할인율을 거의 못 구했다.
  원가를 못 읽어도 할인가 옆(같은 줄 높이 3배 안, 또는 위아래 줄 높이 2배 안에서 가로로 붙음)의 상품 할인율을 쓴다 (`rate_shown`, 검산 안 됨이라 확신도 낮음).
  적립·카드·쿠폰·최대·혜택·포인트 등 문맥의 퍼센트는 쓰지 않고(`RATE_OTHER_WORDS` 확장), 앞에 숫자가 붙은 퍼센트('150%'의 50%)도 할인율로 보지 않는다
- 결과 (Windows OCR, 정답은 이미지로 확인. EasyOCR 캐시 7장은 변화 없음)

### 2. 모델 (`ai/risk/`, 자세한 내용은 `ai/risk/README.md`)

- 한 행 = 결제 화면 팝업 1건. 원시 값 13개(서버 시각 3, check 요청 6, 서버 DB 4) → 모델 특성 17개(모름 표시 3개 포함). 업종과 결제 화면 여부는 뺐다

### 5. 금액을 나중에 채우면 위험도 다시 계산 (사용자 요청)

- 서버 `amount`: 금액을 채운 뒤 `ipp_risk_reassess` — check 때 원시 값에서 금액과 금액 비율(check 시각 기준)만 바꿔 다시 계산하고, 응답에 `risk_updated`와 `risk_*` 칸(check와 같음)

### 결정 사항 (사용자 승인)

- 결제 화면은 위험도와 상관없이 **항상 팝업**, 서버는 `checkout` 이유로 기록. 위험도 모델이 붙으면 문구만 달라지게 판단(code)과 문구(`ipp_reason_text()`)를 나눴다.
- 차단 시간에는 상품 화면에서도 차단 안내 창 + `blocked` 기록. 재표시 간격은 `local_config.json`의 `blocked_repeat_sec`(기본 60초)
- C-1 학습용 OCR 원문 저장은 기본 꺼짐. 켜도 결제 화면은 저장하지 않고 이름/전화번호/주소/카드번호/이메일을 가린다.
- 같은 주문의 기준 시간은 **마지막으로 본 시각부터** 10분 (sliding). 머무르는 동안과 10분 안에 돌아오는 경우는 다시 알리지 않는다.
- 실제 결제 화면 캡처(쿠팡, 무신사)는 사용자가 개인정보를 가려 넣기로 했다. 그전까지는 직접 만든 OCR 샘플로 진행

  - 화면 OCR은 사이트 구조와 상관없이 보이는 글자로 판단하므로 사이트를 늘리기 쉽고, OCR → 쇼핑 화면 분류 → 위험도 예측으로 AI 파이프라인을 만들 수 있다.
