# impulse-guard 진행 상황

## 2026-11-11 · A단계: 방향 전환과 개인 프로젝트 준비 (dev)

### 방향 전환

크롬 확장 프로그램을 보류하고, 팀원의 화면 OCR 쇼핑몰 감지 코드를 중심으로 **데스크톱 감지 프로그램**을 만든다.

- **무엇을 바꿨나**
  - 감지 방식: 쇼핑 사이트 페이지 안의 HTML(선택자)을 읽는 확장 프로그램 → 화면을 캡처해 OCR로 글자를 읽는 데스크톱 프로그램 (`desktop/`)
  - 쇼핑 화면 판별과 가격 분석을 AI(OCR, 분류 모델)로 한다. 전체 기능은 `docs/FEATURES.md`
  - `extension/`은 지우지 않고 보류 표시만 했다 (`extension/README.md` 맨 위)
  - 서버의 토큰 인증 API(`ipp/api/ext.php`)는 데스크톱 프로그램이 그대로 재사용한다. 그래서 `IPP_USE_EXTENSION`은 켜 둔다.
- **왜 바꿨나**
  - 확장 프로그램은 사이트마다 상품명/가격/버튼 선택자를 사람이 맞춰야 한다. 3-3에서 쿠팡은 Tailwind 클래스로 바뀌어 가격을 못 읽었고, 지그재그는 class 이름이 무작위라 가격을 끝내 찾지 못했다. 사이트가 바뀔 때마다 다시 고쳐야 한다.
  - 규칙과 선택자뿐이라 AI 요소가 없다.
  - 화면 OCR은 사이트 구조와 상관없이 보이는 글자로 판단하므로 사이트를 늘리기 쉽고, OCR → 쇼핑 화면 분류 → 위험도 예측으로 AI 파이프라인을 만들 수 있다.

### OCR 가격 오인식 사례

- 원본으로 쿠팡을 분석했을 때 감지된 가격 중 `444366원`처럼 **화면에 없는 가격**이 있었다. OCR이 숫자를 잘못 읽거나 쉼표를 빠뜨린 것으로 보인다.
- 원본은 가격 패턴이 1개만 있어도 쇼핑몰로 판정하므로, 잘못 읽은 값도 판정에 그대로 쓰인다. 서버에 가격을 보내면 고액 판단과 포인트 계산도 틀어진다.
- B-1 가격 분석 모듈에서 거른다: 쉼표 위치 검사, 현실적인 금액 범위, OCR 신뢰도(`readtext`의 confidence), 원가와 할인율로 할인가 검산 등

## 2026-10-28 · 3단계-3: 지그재그 추가와 차단 모드 (feature/extension)

지그재그를 지원 사이트에 추가했다. 회원이 정한 차단 시간에 차단 사이트에 들어가면 사이트 전체를 전체 화면 안내로 가린다.

### 완료

- **사이트 설정** (`extension/sites.js`): 지그재그 상품 상세(`/catalog/products/숫자`)와 장바구니(`/cart`, 확인 필요)
  - class 이름이 무작위인 사이트라 상품명/이미지는 `og:` 메타, 버튼은 글자(`바로구매`, `구매하기`)로 찾는다.
  - 공통 대체값 추가: 가격 선택자로 못 찾으면 `<meta property="product:price:amount">`를 쓴다.
- **manifest.json**: 차단 모드는 사이트 전체에 적용하므로 matches를 도메인 전체로 넓혔다 (`www.coupang.com/*`, `cart.coupang.com/*`, `zigzag.kr/*`, `www.zigzag.kr/*`). 버전 0.3.0
  - 결제 버튼 가로채기와 방문 기록은 그대로 `sites.js`의 `pages`에 있는 페이지에서만 한다.
- **설정 캐시** (`background.js`): 메시지 `ipp:setting`. 성공한 `setting` 응답을 `chrome.storage.session`에 5분(`IPP_SETTING_CACHE_MS`) 보관한다.
  - service worker가 쉬어도 캐시가 남고, 브라우저를 닫으면 지워진다.
  - 서버 주소나 토큰이 바뀌면 캐시를 쓰지 않는다. 실패한 응답은 캐시하지 않는다. `force`면 캐시를 건너뛴다.
  - 차단 종료 시각은 서버가 준 남은 초로 계산한다(`block_until_ms`). PC 시계가 틀려도 남은 시간은 맞다.
- **차단 모드 화면** (`content.js`, Shadow DOM, 불투명 전체 화면)
  - 페이지에 들어가면 캐시된 설정을 보고, 차단 시간 중이고 그 사이트가 ON이면 띄운다. 서버에 연결되지 않으면 띄우지 않는다.
  - 사이트 이름과 종료 시각, 1초마다 줄어드는 남은 시간을 보여 준다. 시간이 끝나면 저절로 사라진다.
  - 버튼: 이 탭 닫기(`ipp:closeTab`), 차단 설정 보기(`ipp:open`으로 `/ipp/setting.php`), 다시 확인(캐시 무시)
  - `blocked` 기록: 안내를 본 시간과 함께 페이지를 떠나거나 안내가 사라질 때 한 번 보낸다. 상품/장바구니 페이지면 상품 정보, 다른 페이지면 주소만 남긴다. 뒤로 가기 캐시에서 다시 보이면 새로 1건을 기록한다.
  - 안내 뒤의 페이지는 `visit`으로 세지 않는다. 안내 뒤에서 키보드로 누른 결제 버튼 클릭은 버린다.

### 남은 이슈

- [ ] **지그재그 가격**: 상품 페이지 가격 선택자가 맞지 않아 항상 0원이다. 지금은 0원 팝업으로 막는다. 진단 코드로 가격 위치를 찾아야 한다.

- [ ] **지그재그 장바구니**: 주소(`/cart`)와 선택자 미확인
- [ ] **차단 모드 브라우저 확인**: 설정에서 차단 시작 → 확장 프로그램 새로고침(캐시 비우기) → 쿠팡/지그재그 홈에서 전체 화면 안내, 남은 시간, 다시 확인

  - `insert_point()` 음수로 차감 (`rel_table = ipp_reward`, `rel_action = exchange`)
  - 잔액 부족, 품절, 사용하지 않는 상품이면 거절
  - 중복 차감 방지: 버튼 비활성화, 페이지마다 주문번호 1개(유니크 키), 회원 단위 `GET_LOCK`으로 잔액 확인부터 차감까지 직렬화
  - 발급 실패 시 같은 금액을 환불(`rel_action = refund`)하고 재고를 되돌림

### 남은 이슈

- [ ] **실제 기프티콘 API 연동**: 업체 선정 후 `ipp_gifticon_issue()` 교체. 바코드 이미지(`cp_barcode_url`)는 지금 비어 있다.
- [ ] **사용 여부 동기화**: 지금은 회원이 직접 "사용 완료"를 누른다. 실제 API에서는 사용 여부 조회로 바꿔야 한다.
- [ ] **`pending`으로 남는 쿠폰**: 포인트를 차감한 뒤 발급 API 응답 전에 요청이 끊기면 쿠폰이 `pending`으로 남고 포인트는 환불되지 않는다. 일정 시간이 지난 `pending`을 찾아 API 조회 후 발급 완료 또는 환불(`cancelled`)하는 정리 작업이 필요하다.
- [ ] **관리자 페이지**: 리워드 등록/수정, 재고, 노출 관리를 위한 `adm/ipp_reward_*.php`가 없어 지금은 DB에서 직접 고친다.
- [ ] **리워드 이미지**: 시연 데이터의 `rw_image`가 비어 있어 기본 아이콘(🎁)으로 표시된다.
- [ ] **기존 리워드샵 상품 정리**: 영카트 쇼핑몰의 임시 리워드 상품(`ca_id=10`)이 아직 남아 있다. 숨김 또는 삭제 결정 필요.
- [ ] **만료 쿠폰 정책**: 쓰지 않고 만료된 쿠폰의 포인트를 돌려줄지 결정 필요 (현재는 환불 없음).
- [ ] **시연 SQL 반복 실행**: `002_gifticon.sql`을 다시 실행하면 시연 리워드가 중복으로 들어간다.
