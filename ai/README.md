# impulse-guard AI: 충동구매 위험도 예측

규칙 기반 감지(`ipp_detect_impulse()`)를 학습 모델로 바꾸기 위한 폴더입니다.
4단계-1에서는 **환경과 데이터**를 만들었습니다. 모델 학습과 서빙(FastAPI)은 4단계-2에서 합니다.

## 1. 왜 규칙을 모델로 바꾸나

지금 규칙 (`ipp/lib/bank.lib.php`):

```
차단 키워드가 있으면 충동구매
또는 (업종이 쇼핑/패션/게임/배달) 이고 (23~4시 이거나 5만 원 이상) 이면 충동구매
```

| 규칙의 문제 | 모델로 바꾸면 |
|---|---|
| 결과가 0/1뿐이라 "얼마나 위험한지"를 말할 수 없다 | 0~1 사이 확률(위험도)을 준다. 위험도에 따라 개입 강도를 바꿀 수 있다 |
| 경계에서 결과가 급변한다 (49,999원은 안전, 50,000원은 위험 / 22:59는 안전, 23:00은 위험) | 금액과 시각이 위험도에 연속적으로 반영된다 |
| 모든 회원에게 같은 기준(5만 원)을 쓴다. 월 소비 30만 원인 사람과 300만 원인 사람이 같다 | 회원 평균 대비 비율로 개인 기준을 반영한다 |
| 조건을 사람이 정하고, 조건끼리의 상대적 중요도를 모른다 | 데이터에서 각 특성의 영향 크기를 배운다. 쌓이는 쿨다운 결과로 다시 학습할 수 있다 |
| 체류 시간, 방문 반복처럼 확장 프로그램이 모으는 행동 신호를 쓰지 못한다 | 행동 신호를 특성으로 넣는다 |

## 2. 데이터 형식

한 행 = **쿨다운 1건** (사용자가 구매를 고민한 순간). 열 정의는 [`features.py`](features.py)에 고정되어 있고, 가상 데이터, 실제 데이터 추출, 이후 학습과 서빙이 모두 이 파일을 씁니다.

| 열 | 설명 |
|---|---|
| `user` | 회원 식별값. **특성이 아님.** 학습/평가를 회원 단위로 나눠 같은 사람이 양쪽에 섞이지 않게 할 때만 쓴다 |
| `hour`, `weekday` | 고민을 시작한 시각(0~23), 요일(월=0) |
| `amount` | 금액(원) |
| `amount_ratio` | 금액 ÷ 그 시점 이전 90일 회원 평균 결제액. 이전 결제가 3건 미만이면 1.0 |
| `category` | shopping, fashion, game, delivery, food, transport, etc |
| `has_pressure` | 상품명에 할인/압박 문구(세일, 할인, 특가, 마감, 한정, 오늘만, 타임딜, 품절임박, 마지막, 1+1, N%)가 있으면 1 |
| `stay_sec` | 상품 페이지 체류 시간(초). 모르면 빈 값 |
| `visits_24h` | 직전 24시간 같은 사이트 방문 수 |
| `days_since_payday` | 가장 최근 월급일(25일 가정) 이후 경과일 |
| `label` | **정답**: 쿨다운 결과가 `failed`(참지 못하고 결제)면 1, `gaveup`(바로 포기)/`success`(끝까지 참음)면 0 |

### 정답을 이렇게 정한 이유

- 쿨다운은 "사고 싶은 물건을 일단 담아 두고 기다리는 것"이다. 그래서 그 결과가 **그 순간의 구매 욕구가 충동이었는지**를 가장 직접 보여 준다.
  - 기다리지 못하고 샀으면(`failed`) 충동에 진 것이다.
  - 포기했거나 끝까지 참았으면(`gaveup`, `success`) 충동이 아니었거나 이겨낸 것이다.
- `waiting`(진행 중)은 결과를 모르므로 뺀다.
- 거래 내역의 `tr_is_impulse`는 쓰지 않았다. 그 값은 지금 규칙이 붙인 것이라, 그걸 정답으로 쓰면 모델은 규칙을 흉내 내는 것만 배운다.

## 3. 특성별 근거

각 특성에 대해 "넣은 이유 → 데이터 출처 → 예상 방향"을 적었습니다. 근거가 연구에서 오는 것과 **우리 가설**인 것을 구분했습니다.

### 시각 (`hour`)
- **이유**: 하루가 끝나 갈수록 자기통제가 약해진다는 연구가 있다(자기조절 자원 고갈, Baumeister 외 1998; 충동구매와의 연결은 Vohs & Faber 2007). 다만 자원 고갈 이론은 대규모 재현 연구(Hagger 외 2016)에서 효과가 확인되지 않아 논란이 있다. 그래서 "피곤하고 혼자 있는 심야에 충동구매가 많다"는 정도의 가설로 쓴다. 지금 규칙도 23~4시를 위험 시간으로 본다.
- **출처**: 쿨다운 시작 시각
- **예상 방향**: 심야 > 늦은 저녁 > 낮

### 요일 (`weekday`)
- **이유 (가설)**: 주말에는 여가 시간이 길어 쇼핑 앱/사이트를 둘러보는 시간이 늘고, 목적 없이 구경하다 사는 경우가 많다.
- **예상 방향**: 주말 > 평일

### 금액 (`amount`)과 회원 평균 대비 비율 (`amount_ratio`)
- **이유**: 같은 5만 원도 사람마다 무게가 다르다. 사람은 돈을 머릿속에서 용도별 계정으로 나눠 관리하고(심리적 회계, Thaler 1985, 1999), "평소에 비해 큰 지출인지"로 판단한다. 지금 규칙의 고정 기준(5만 원)이 이 차이를 반영하지 못한다.
- **출처**: 쿨다운 금액, 그 시점 이전 90일 거래(`g5_ipp_transaction`) 평균. 미래 정보가 섞이지 않게 **그 시점 이전** 거래만 쓴다.
- **예상 방향**: 비율이 클수록 위험. 절대 금액도 함께 넣어 모델이 둘의 비중을 정하게 한다.

### 업종 (`category`)
- **이유**: 즐거움을 위한 소비(쾌락재: 옷, 게임)는 필요를 위한 소비(실용재: 교통, 식료품)보다 정당화가 어렵고 감정적으로 결정되는 경향이 있다(Dhar & Wertenbroch 2000).
- **출처**: 사후 감지 쿨다운은 거래 업종, 확장 프로그램 쿨다운은 쇼핑몰(shopping), 모르면 etc
- **예상 방향**: 패션/게임/쇼핑 > 식비/교통

### 할인·압박 문구 (`has_pressure`)
- **이유**: "오늘만", "한정", "품절 임박"은 희소성과 긴급성을 만들어 생각할 시간을 줄인다(Cialdini, 『설득의 심리학』의 희소성 원리). 지금 규칙의 기본 키워드(세일, 할인, 특가)를 넓힌 것이다.
- **출처**: 상품명 정규식. 상품명 원문은 데이터에 남기지 않는다.
- **예상 방향**: 있음 > 없음

### 상품 페이지 체류 시간 (`stay_sec`)
- **이유**: 충동구매는 "갑작스럽고 강한, 즉시 사고 싶은 욕구"로 정의된다(Rook 1987). 빠르고 직관적인 판단(시스템 1)과 느리고 따져 보는 판단(시스템 2)을 나누면(Kahneman 2011), 짧게 보고 결정할수록 따져 보는 과정이 적다.
- **출처**: 크롬 확장 프로그램의 `visit` 기록(`g5_ipp_block_log.bl_stay_sec`). 확장 프로그램 밖에서 만든 쿨다운은 값이 없다(빈 값).
- **예상 방향**: 짧을수록 위험

### 최근 24시간 같은 사이트 방문 수 (`visits_24h`)
- **이유 (가설)**: 하루에 같은 쇼핑몰을 여러 번 드나드는 것은 사고 싶은 마음이 계속 맴돈다는 신호다. 확장 프로그램이 모으는 행동 데이터로만 알 수 있는 특성이다.
- **출처**: `g5_ipp_block_log`의 `visit` 수
- **예상 방향**: 많을수록 위험

### 월급일 이후 경과일 (`days_since_payday`)
- **이유**: 소득이 들어온 직후 소비가 늘어난다는 연구가 있다(Stephens 2003: 지급일 직후 소비가 늘고 다음 지급일 전에 줄어듦). 통장에 돈이 많아 보일 때 지출 통제가 느슨해진다.
- **출처**: 쿨다운 날짜와 월급일(25일 가정)
- **예상 방향**: 월급일 직후(5일 이내) 위험

## 4. 가상 데이터를 쓴 이유

[`data/generate.py`](data/generate.py)로 5,000건을 만들어 먼저 학습합니다.

1. **실제 정답이 거의 없다**: 2026-10-28 기준 결과가 정해진 쿨다운은 2건(모두 `gaveup`)이고 `failed`(=1)는 0건이다. 한쪽 정답만으로는 학습할 수 없다.
2. **정답이 늦게 나온다**: 쿨다운 결과는 24시간이 지나야 정해진다.
3. **콜드 스타트**: 서비스를 시작하는 순간부터 위험도를 보여 줘야 하는데, 그때는 데이터가 없다.
4. **파이프라인을 먼저 검증한다**: 데이터 형식 → 학습 → 서빙 → PHP 연동을 가상 데이터로 끝까지 연결해 두면, 실제 데이터가 쌓였을 때 `export.py` 결과로 바꾸기만 하면 된다.
5. **개인정보**: 개발/발표 과정에서 실제 회원의 소비 기록을 쓰지 않는다.

### 가상 데이터를 만드는 방법

- 회원 300명. 회원마다 평소 결제 수준(중앙값 약 3만 원), 숨은 충동 성향, 쇼핑몰 방문 습관이 다르다.
- 회원마다 180일 동안의 "평소 결제 내역"을 따로 만든다. `amount_ratio`는 실제 추출과 같은 규칙(직전 90일 평균)으로 계산한다.
- 고민 시각은 점심, 저녁, 심야에 몰리게 뽑는다.
- 충동 확률은 3장의 예상 방향을 로지스틱 식으로 더해 정하고(`EFFECTS`), 회원별 성향과 노이즈를 더한다. 전체 충동 비율은 약 30%로 맞춘다.
- 기록 오류를 흉내 내 정답의 3%를 뒤집는다. 체류 시간의 15%는 빈 값으로 둔다(확장 프로그램 밖에서 만든 쿨다운).
- seed가 같으면 항상 같은 파일이 나온다 (기본 seed 42).

결과(seed 42): 5,000건, 충동 31.2%. 조건별 비율은 `python data/describe.py data/synthetic.csv --plot data/synthetic.png`로 볼 수 있다.

| 조건 | 충동 비율 |
|---|---|
| 낮 4~18시 / 심야 23~4시 | 26% / 45% |
| 회원 평균 대비 0.7배 미만 / 3배 이상 | 19% / 52% |
| 압박 문구 없음 / 있음 | 26% / 40% |
| 교통 / 패션 | 16% / 36% |
| 체류 30초 미만 / 10분 이상 | 40% / 21% |
| 월급일 후 5일 이내 / 이후 | 38% / 30% |

## 5. 한계 (발표에서 숨기지 않을 것)

1. **순환성**: 가상 데이터의 패턴은 **우리가 정한 가정**이다. 모델은 그 가정을 다시 배울 뿐이므로, 가상 데이터에서 성능이 좋아도 **실제 사용자에게 잘 맞는다는 증거가 아니다**. 가상 데이터가 증명하는 것은 "파이프라인이 동작한다"와 "이런 패턴이 있으면 모델이 잡아낸다"까지다. (같은 이유로, 가상 데이터에서 지금 규칙과 정답의 일치율이 57%로 나오는 것도 규칙이 나쁘다는 증거가 아니다.)
2. **효과 크기는 임의값이다**: 연구는 방향(심야에 위험하다)을 알려 줄 뿐, "심야면 로그오즈 +1.2" 같은 크기는 우리가 정했다.
3. **선택 편향**: 실제 정답은 사용자가 쿨다운에 담은 상품에만 생긴다. 이미 한 번 망설인 구매만 데이터가 되므로, 망설임 없이 바로 산 충동구매는 빠진다.
4. **정답 품질**: `failed`는 쿨다운 기간에 **상품명과 가맹점명이 같은 결제**가 있을 때만 잡힌다(`ipp_cooldown_settle()`). 다른 곳에서 사면 `success`(0)로 잘못 들어간다. 즉 실제 데이터의 1은 적게 잡힌다.
5. **월급일은 가정값(25일)이다**: 회원별 월급일 데이터가 없다. 입금 내역이 연동되면 회원별로 추정해야 한다.
6. **체류 시간은 페이지를 떠날 때 기록된다**: 팝업에서 고민한 시간까지 섞인다.
7. **회원 수와 기간**: 300명, 180일은 시연용 규모다. 실제 서비스의 사용자 분포와 다를 수 있다.

### 실제 데이터로 넘어가는 계획

1. 서비스를 쓰면서 쿨다운 결과가 쌓이면 `data/export.py`로 같은 형식의 CSV를 뽑는다.
2. 실제 데이터로 **평가만** 먼저 해 본다 (가상 데이터로 학습한 모델이 실제에서도 맞는지).
3. 실제 데이터가 충분해지면 실제 데이터로 다시 학습하고, 가상 데이터는 버리거나 보조로만 쓴다.

## 6. 실행 방법

Python 3.13 기준. 모든 명령은 `ai/` 폴더에서 실행합니다.

```powershell
cd c:\projects\youngcart\gnuboard5.6.43\ai
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 가상 데이터 5,000건 → data/synthetic.csv
.venv\Scripts\python.exe data\generate.py

# 조건별 충동 비율 표와 그래프 (발표 자료용)
.venv\Scripts\python.exe data\describe.py data\synthetic.csv --plot data\synthetic.png

# 실제 DB → data/real.csv (그누보드 data/dbconfig.php의 접속 정보 사용, SELECT만 함)
.venv\Scripts\python.exe data\export.py
```

- 콘솔에서 한글이 깨지면 `$env:PYTHONIOENCODING = 'utf-8'`을 먼저 실행합니다.
- 만든 CSV/PNG는 Git에 올리지 않습니다(`ai/.gitignore`). 특히 `real.csv`는 회원 데이터입니다. 회원 아이디는 실행할 때마다 바뀌는 salt로 HMAC해서 남기고, 상품명은 남기지 않습니다.
- `export.py`의 DB 접속 정보는 환경변수 `IPP_DB_HOST`, `IPP_DB_USER`, `IPP_DB_PASSWORD`, `IPP_DB_NAME`, `IPP_DB_PREFIX`로 바꿀 수 있습니다.
